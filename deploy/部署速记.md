# 容器部署

从后端仓库根目录复制 `.env.example` 为私有的 `.env`，填写 Mongo 连接串、数据库名、至少 32 字节的随机 JWT 密钥和对外的资源地址。启动器将单节点标准端口连接串的主机替换为 `mongo:27017`，保留认证信息、库名和查询参数。Compose 使用 `seaweedfs:8333`；匿名网关显式留空两个 S3 密钥，启用认证时成对填写。可用 `BACKEND_ENV_FILE` 指定其他运行环境文件。

```sh
docker compose -p cup-backend -f docker-compose.yml.example config --quiet
docker compose -p cup-backend -f docker-compose.yml.example up -d --build backend
```

前后端分别使用独立 Compose 项目，加入同一个已有网络（`TWILIGHT_NETWORK` 默认 `twilight_cup_default`）。Mongo 和 SeaweedFS 由部署者单独维护。网络内通过 `backend:8100` 和 `frontend:8080` 访问。网关路由参考同目录的 `twilightcup.conf`，部署者提供自己的域名和证书。

主机端口默认为回环地址的 8100 和 5174。后端可通过 `BACKEND_BIND_IP` 选择 LAN 地址，`BACKEND_PORT` 调整主机端口。生产需同时保留已有的两个非回环绑定地址。将前后端的绑定变量设为第一个现有地址，再用部署者私有的 Compose override 为两个服务追加第二个地址（后端 `<第二绑定地址>:8100:8100`，前端 `<第二绑定地址>:5174:8080`）。应用服务均不自动重启。26 张生产专用背景由部署者从授权素材备份提供给前端。

Docker 构建直接读取本仓源码和语言包，使用固定基础镜像及带哈希的运行依赖。更新 uv.lock 后同步导出：

```sh
uv export --frozen --no-dev --no-emit-project --no-header --format requirements-txt > runtime-requirements.txt
```
